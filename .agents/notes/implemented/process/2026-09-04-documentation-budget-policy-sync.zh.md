# Agent Note: 文档预算规范同步

Status: implemented

## Problem

初始化器预算门禁过去只约束根 `AGENTS.md`，而源模板还为文档子树规定了独立目标、余量和“先迁移”的处理流程。因此，初始化的项目没有继承源模板的完整文档规范。

## Decision

启用 `docBudgets` 时，初始化器现在会物化 `docs/AGENTS.md`，并为两个常设指令文件设置机械上限：根文件 1900 词，`docs/AGENTS.md` 1320 词。统一规范同时规定编辑目标：根文件 1600 词、普通子树指令文件 600 词、`docs/AGENTS.md` 1250 词，并至少保留 5% 余量。门禁变红时先迁移内容，再压缩；提高上限须在同一变更中说明理由。

当前决策使用初始化器拥有的 `.vibe-init/` 工具链和 standalone install 文档；旧 `.dsh-vibe/` 命名空间不被发现或迁移。所有权边界与移除理由见[独立硬切 Note](../simplification/2026-09-06-standalone-vibe-init.zh.md)。

## Alternatives considered

**只保留根文件上限。** 维持旧的最小配置，却会让文档规范没有边界，并偏离源模板。

**为每个 Markdown 文件设置预算。** 这会把预算变成削减目标并重复层级归属；未列入清单的文档交由评审控制更合适。

**只写编辑目标而不设门禁。** 依赖记忆，无法机械发现常设文档缺失或超长。

## Consequences

`docs/AGENTS.md` 成为受管项目文件，并像其它指令文件一样排除在双语配对之外。预算清单现在是逐文件上限的权威来源；修改常设文档时，必须同步保持清单条目和规则包源文件摘要一致。文档当前只说明初始化器拥有的面和 standalone install 路径，不承担旧命名空间的迁移责任。
