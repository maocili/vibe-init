# Agent Note: 精简根级 Agent 指令

Status: implemented

## Problem

根 `AGENTS.md` 及其受管规则段用中英文重复披露相同义务，并在每次会话中注入 Agent Note 模板、生命周期机制、文档流程和提交节奏等细节。这些细节本应由下层规则文档拥有，却持续占用上下文，并脱离具体任务限制 Agent 的规划方式。

## Decision

vibe-init 自有的所有 `AGENTS.md` 及会物化到其中的受管规则包源文件统一使用英文，不附加中文摘要。仓库根文件只保留仓库定位、产品与内容源边界、验证命令和导航链接。每个根级受管规则段只陈述一句持久契约，并指向拥有详细工作流的文档或技能。marker 外的项目内容仍由用户拥有，不会为了语言一致性而被改写。

规则包不再要求每完成一个可独立验证的步骤就提交一次。提交粒度由具体任务或仓库工作流决定，不再作为常驻注入的通用指令。Agent Note 的格式与生命周期细则仍由 [Agent Note 规则](../../README.zh.md)拥有；文档归属和预算处理流程仍由[文档规范](../../../../docs/AGENTS.md)拥有。

该决策只收窄根级指令的呈现方式，不移除 Agent Note、文档预算、相对链接校验、双语文档交付，也不改变[实现设计](../architecture/2026-09-04-vibe-init-implementation-design.zh.md)定义的所有权与升级行为。它细化[文档预算策略](../process/2026-09-04-documentation-budget-policy-sync.zh.md)确立的根文件呈现方式，但不改变机械预算上限。

## Alternatives considered

**保留双语摘要但压缩两侧。** 这仍会让每条保留规则占用两份常驻上下文，并维持可能漂移的两个副本。

**保留根文件中的详细规则，并提高或维持预算。** 更高的篇幅额度无法解决内容归属和渐进式披露问题，只会允许位置错误的流程细节继续常驻。

**彻底删除详细规则。** 这会丢失有用的契约与验证流程。将其保留在所属文档和技能中，可以按需披露而不损失信息。

**保留每步强制提交。** 这种做法通过强制增加检查点改善可追溯性，并隔离评审或回滚边界，却阻止 Agent 按任务选择合适的原子变更边界，还会把版本控制偏好变成通用规划约束。此前的强制提交节奏决策由本 Note 完全取代。

**要求每条命令或每个文件编辑后提交。** 这些操作不一定构成可独立验证的变更，因此只会产生嘈杂历史，不能提供有意义的恢复边界。

## Consequences

Agent 只需加载更小的英文单语根契约，在任务进入相关子树或调用对应技能时才读取细则；具体任务或仓库工作流仍可要求在有意义且已验证的边界提交。测试会拒绝 vibe-init 自有的所有物化 `AGENTS.md` 中的中文，并拒绝物化根规则中的双语摘要、Agent Note 模板标题和提交节奏指令，同时继续覆盖 marker 所有权、特性开关和幂等升级。
