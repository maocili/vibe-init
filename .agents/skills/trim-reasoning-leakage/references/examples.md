# Durable-prose examples

These examples calibrate the distinction between a durable repository fact and private change or review context. Treat them as principles, not copy-ready text.

## Replace a dead process reference

**Leaked:** “The registry rejects duplicate names (decision 7).”

**Durable:** “The registry rejects duplicate names.”

If a committed document owns the rationale, link to it. Otherwise retain the factual clause and remove the unresolvable label.

## State the mechanism, not the patch story

**Leaked:** “This PR replaced undefined color tokens with aliases.”

**Durable:** “Colors use the alias tokens; an undefined token renders the fallback.”

Keep the present behavior and an important counterfactual. Put patch history in an Agent Note or the review system.

## Preserve obligations and evidence

Do not shorten away a real obligation (“pending migration to slots”), a measured bound, a justified lint suppression, a durable issue reference, or the distinction between a hypothetical and a shipped feature. Delete clauses rather than whole sentences when a line mixes history with a current contract.
