# Supersession and lifecycle changes

Use this workflow when adding an Agent Note or materially changing the decision owned by one.

## Check the active corpus

Search active notes for the same decision, mechanism, or rejected alternative. The scope should cover
every plausible match, not merely files named like the new note. Classify each match as full
supersession, partial supersession, or independent rationale.

- For full supersession, consolidate the prior record only after the current owner preserves every
  unique rationale, alternative, consequence, shipped verification fact, and named gap. Repair inbound
  links, then remove the complete obsolete active record and all declared sibling files.
- For partial supersession, keep both records active and add reciprocal relative links in the same
  change.
- Keep independent rationale active and cross-linked when the relationship helps future readers.

Resolve every known match in the same change. Do not defer it to a later corpus audit. If a fully
superseded implemented record still qualifies for historical retention, follow
[archive operations](archive-operations.md) rather than leaving the obsolete owner active. If an
obsolete proposal never shipped, reject it with an honest reason. Delete a rejected record only after
the retention criteria show that it no longer prevents a plausible mistake.

## Apply the target lifecycle

Follow the project's Agent Note format and the instructions for the target lifecycle. An unbuilt or
partly built decision remains proposed. A shipped decision moves to implemented and describes current
behavior rather than plans. A declined proposal moves to rejected and preserves the rationale only
while that verdict remains a useful guardrail.

Update bilingual counterparts and their declared consistency record together. Run the project's Agent
Note format, classification, pairing, and link checks that apply to the changed files.
